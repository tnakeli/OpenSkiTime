Code signing
policy.

How Windows releases are built, approved and signed.

Current status

Windows releases are digitally signed with a Certum Open Source Code Signing certificate issued to Teemu Niemi, the project maintainer. The private key is kept in Certum’s cloud hardware security module (SimplySign) and never leaves it. Releases published before signing was enabled are unsigned and say so in their release notes.

A new signed release can still trigger a Windows SmartScreen warning until it has built a download reputation. A valid signature shows who published the file; it does not hide that warning.

Check a download

Download only from the project’s GitHub Releases. Before running the installer, right-click it, choose Properties → Digital Signatures and check that the signer is Teemu Niemi, the signature is valid and it has a timestamp. In PowerShell, Get-AuthenticodeSignature .\OpenSkiTime-X.Y.Z-win-x64-setup.exe must report Valid. The certificate thumbprint that every release is checked against is published in the source repository. You can also compare files with the published SHA256SUMS.txt.

What is signed

Only OpenSkiTime’s own release files are signed: the Windows installer, its uninstaller, and the OpenSkiTime executables and libraries it contains, including the Timy USB helper. Signatures use SHA-256 and a trusted timestamp, so they stay valid after the certificate expires. They are built from the public source repository by GitHub Actions from a protected vX.Y.Z tag on the reviewed master branch. Locally built files and files from forks are never signed.

Third-party components distributed with OpenSkiTime, such as the .NET runtime, keep their upstream publishers’ signatures and are not re-signed as OpenSkiTime. Vendor drivers and SDKs, such as ALGE software, are not distributed or signed by this project.

Team roles

  • Committers and reviewers: Teemu Niemi (@tnakeli, tniemi@gmail.com), maintainer. Changes from other contributors are merged only through reviewed pull requests.
  • Approvers: Teemu Niemi (@tnakeli, tniemi@gmail.com). Each release is signed only after the approver enters a one-time code from the SimplySign mobile app for that specific release. No reusable signing secret is stored in GitHub or in the build system.

All team members use multi-factor authentication for GitHub and for the signing service.

Release process

Each release passes automated build, test and installer checks before it is signed. After signing, every signature is checked against the published certificate, and the signed installer, dependency (SBOM) and vulnerability checks run again before publication. High and critical known vulnerabilities block publication. Release notes are published with every version, and release tags are never moved after publication.

Privacy

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. Online features such as FIS lookups, weather forecasts and live publishing are started by the operator. See Privacy & your race data for details.

Report a problem

If you find a signed file that you believe was not released by this project, or another security issue, report it privately through GitHub security advisories or by email to the maintainer, Teemu Niemi, at tniemi@gmail.com.
