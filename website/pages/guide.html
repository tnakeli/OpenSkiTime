01 / PREPARE

Create your event series.

Create a new series and save its .ost file in a folder you can back up. Add the competitions, dates, disciplines and runs. Register a small set of fictional competitors and review their participation.

Each series file holds race data, raw timing input and correction history. Use the application’s Backup / transfer action to make a consistent copy.

02 / START LISTS

Know who starts next.

Select a competition and run, prepare the first-run draw and inspect the order. For a two-run race, prepare Run 2 after reviewing the Run 1 classifications.

Current draw support covers standard two-run SL/GS and single-run DH/SG. Check the repository’s scope before using other formats.

03 / TIMING

Rehearse the whole run.

Choose the simulator in Settings, then practice starts, intermediate times, finishes and DNS/DNF/DSQ classifications. Review At start, Running, Timestamps and Ranking together.

For physical equipment, configure the supported adapter and verify all channels. ALGE native USB needs the vendor’s Windows driver and SDK; these are not bundled.

Practice corrections with an operator and reason, reconnect the device and rehearse with independent backup timing. Physical-device operation still needs verification on the actual setup.

04 / LIVE RESULTS

Publish when you choose.

Open Live timing and choose Local or Cloud. Local publishing needs no account or key. For cloud publishing, enter the server address and save the server’s publisher key in Settings → Live timing, then press Start and share the competition’s generated link with viewers. The server’s front page also lists every race it is currently publishing.

You can run your own live timing server; see the live timing server guide. To publish on the developer’s hosted service at https://live.openskiti.me, contact the OpenSkiTime maintainer through GitHub to request a publisher key.

The link opens unofficial results in a browser. Cloud publishing may take a moment to wake up. Local timing capture continues independently of online publishing.

Cloud state is temporary. After the service sleeps or restarts, an active publisher restores the current snapshot. Closing the publisher means the public view may become unavailable; it is not a permanent results archive. Stop pauses publishing. Delete All Data removes the session’s current cloud view.

Keep live publishing active during the event. A paused view can remain connected while viewers have it open.

05 / RESULTS

Review before exporting.

Check classifications, race information and calculations with the technical delegate. Record approval and export the saved XML revision. FIS submission is currently limited to test mode.

Optional B and hand timing evidence support timing-report preparation. Rehearse the complete workflow before race day.

06 / PDF FACTORY

Generate the race paperwork.

Open PDF Factory and choose the competition from its navigation menu or the shared header. Generate entry lists, saved start lists, referee forms, penalty calculations, approved official results and timing reports from committed race data.

Each row shows its filename and freshness status. Generate All skips reports whose prerequisites are missing. Open launches the generated PDF directly from the folder beside your event file; hover over the filename or Open button to see the full path. Regenerate refreshes an outdated file.

Expand PDF settings to choose an optional A4 background and margins. Preview opens a page with the content box and the four margin labels. Referee reports use their own fixed margins and FIS form layout, without the background's header or footer. The default form fits one page; DSQ, DNS, NPS and DNF tables expand and continue onto further pages as needed.

FOR DEVELOPERS

Run from source.

Install the .NET 10 SDK on Windows and clone the repository.

git clone https://github.com/tnakeli/OpenSkiTime.git
cd OpenSkiTime
dotnet restore OpenSkiTime.slnx
dotnet build OpenSkiTime.slnx -c Release
dotnet run --project src/OpenSkiTime.Desktop -c Release
dotnet test OpenSkiTime.slnx -c Release

Find detailed device, timing, live publishing and result guides in the repository documentation.
