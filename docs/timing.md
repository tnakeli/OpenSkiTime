# Timing setup and operation

## Open the race

Run 2 start lists show each starter's saved Run 1 time in the grid, TSV export and printable HTML. The time comes from the Run 1 results used to create that starting order. Before Run 2 starts, the list can be exported only while those Run 1 results still match the current Run 1 results; audited Run 1 changes that leave the results unchanged, such as an ignored stray impulse, do not block it. Once Run 2 timing has begun, its list can always be exported. In the manual Run 1 result editor, enter the status by name (Finished, DNS, DNF, DSQ or NPS).

Prepare and save a start list in **Start lists**, then choose **Timing → competition short name → Run**. After that, clicking **Start lists** or **Timing** opens the selected competition and run immediately; the menu remains available for switching. The selection stays visible beside OpenSkiTime in the top bar. The run and codex also appear in the race view. The run starts automatically when the first start impulse is assigned to a competitor; connecting the clock alone does not start it. Assign the Start, Finish and intermediate timing roles (source, connection and channel) in **Settings → Timing devices & clocks** and save them on this computer; see [Settings](settings.md#timing-devices). Timing connects automatically on entering a run or returning from Settings when saved preferences exist. The connection banner reports the source and its current status. **Device time** shows the latest clock value received from the device, extrapolated briefly between messages; dashes mean no recent device time is available. Check the physical clock if the display is stale.

The current competition and run are marked **ACTIVE** and **OPEN** in the selection menu. Selecting them opens that race view. You can create another competition while timing remains connected; changing registration (including saving competitor desk changes and competitor imports) or redrawing a captured start list still requires the timing capture to stop.

The header switches **START**, **I1**, **I2**, etc., and **FINISH** on or off independently. On entering Timing or connecting a source, all configured positions begin in **HOLD**; resume each one after checking the race and device. Returning from another view or changing runs puts them back in HOLD. Merely reopening the current Timing menu while staying in the view does not. HOLD is an application attribution state, not a command to stop the physical clock. Original input is still saved, but new impulses are not assigned to competitors until that position is resumed. Changing runs while connected applies HOLD inside the capture writer before any further input is processed. Automatic assignment (expected bib or explicit device bib) also leaves an impulse unassigned for review when it cannot belong to that competitor: an impulse older than one already assigned at the same position on the same clock (for example a trigger recovered later from device history), an intermediate or finish that is not after the competitor's own start, or input from before a live run change (for example ALGE Results history of the previous run read again). Recovered history pages are assigned in device-time order, not in page order. Running and Timestamps show a column for each intermediate enabled in the competition and mapped to a channel in Settings, including while the position is on HOLD. Changing the competition's count updates Timing when you return, without redrawing the start list. Add an intermediate role in Settings and reconnect before using a newly added intermediate. Timy intermediate channels may remain configured when a competition has no intermediates: their impulses are preserved as raw input and ignored for that competition. Removing an intermediate from either the competition or the configured intermediate roles hides its column without deleting previously recorded raw input or audit history. Intermediate roles are numbered in course order, for example channels C2 and C3 for I1/I2. Start and finish default to C0 and C1.

The workspace has four grids. **At start** shows the waiting starters with the next starter at the bottom; in Run 2 it also shows each racer's Run 1 time. **Running** shows only racers on course, with the next expected finisher at the bottom and configured intermediate columns. **Timestamps** shows recorded times of day, including unassigned impulses, with the most recently received impulse at the top. **Ranking** shows finishers and classifications, grouped by category when rules exist. Its time column is named after the current run (**RUN 1**, **RUN 2**) and shows DNF/DSQ and other states in place of a time. Each configured intermediate has a column with the split time and, in parentheses, the rank at that intermediate in this run, for example `0:20.00 (2)`; every valid split time of the run counts, including racers still on course or later classified. From Run 2 on, a column for the previous run shows its time and the racer's rank in that run; the ranking itself and **TOTAL** follow the combined time, as before. These ranks are counted within the same category group as **RK**. Equal times share one rank (ex aequo, for example 1, 1, 3) and are listed with the higher bib first, exactly as in Results, the official results PDF and the result XML (ICR 617.3.3). Drag the dividers to allocate space. The connection persists when moving between views and runs; entering Timing reconnects a saved source if it has been disconnected.

Start and finish expectations normally follow the actual race order. In **At start**, drag a waiting racer to the upper or lower half of another row; the highlighted edge shows exactly where they will land. Dropping in empty At start space moves a waiting racer to next. You can also select a racer and use **Ctrl+Up/Down** to move them one place. The bottom racer starts next. **F5** moves a selected racer directly to next at start; **F6** chooses the expected finisher. Start-order moves are saved and audited in the event file without changing the original draw. **Shift+F5** marks the absent next starter DNS. Select several racers with Ctrl/Shift and click a status button or use the right-click status menu to classify all selected racers together. Dragging a racer onto a status button classifies only that racer. **Shift+F10** opens the status menu; the remaining shortcuts still work without menu items. **Ctrl+F5/F6** hold or resume start/finish attribution. A valid finish appears immediately with its time and rank. A false finish can be ignored with **Ctrl+Backspace**. Ignored impulses remain visible in Timestamps. **Shift+F5** and **Ctrl+Backspace** act on the starter and finish impulse shown on screen; if new input changed them since the last refresh, the action is refused with a message and nothing is changed. Ending a drag keeps the current selection, and a refresh never selects a competitor after the operator cleared the selection. The classification editor applies to one selected competitor; with several selected, use a status button or the status menu.

Drag a competitor from any grid to **At start** to restart that racer, including after a finish or classification. Existing impulses and corrections are retained in the raw journal and audited as superseded; the next start impulse begins a new attempt. Drag a competitor onto an actual Start, Interm or Finish cell in **Timestamps** to assign that pulse. When an occupied timestamp is reassigned, its former owner returns to the course for another timestamp. While a competitor is held over an Interm or Finish cell, a small preview shows the bib and the time that competitor would receive, always measured from their own start (for example `Intermediate 2: 0:52.50` or `Finish: 1:13.31`). It uses the same clock, precision, two-hour and truncation rules as results. If the competitor has no usable start, or the timestamp is before their start or otherwise invalid, the preview says so instead of showing a time. The preview reads only the times already loaded and changes nothing until the timestamp is dropped; Start cells show no preview. Numeric time changes are not available in the race UI. Original input and audit remain unchanged by layout, grouping and selection.

**CURRENT** is a display estimate using device time and a monotonic local clock. Final results subtract recorded impulses at full input precision and truncate to hundredths. Missing or conflicting timing displays **No time**. After all racers finish or are classified, **Prepare Run 2** creates the next run's start-list workflow without disconnecting capture. Finish or classify everyone on course before switching the active run.

## ALGE Timy 2 / Timy 3 native USB — Windows x64

- Install the manufacturer's [Timy USB driver](https://alge-timing.com/alge/download/driver/TimyUSB_Driver_Setup_2.80.0.exe) once, using an administrator account when Windows requests it. Native Timy USB is not a virtual COM port. Check Device Manager if the device remains unknown or reports a missing driver.
- In OpenSkiTime, select **Timy 2/3 · USB → Set up USB library** once while online. This downloads the manufacturer's [USB library package](https://alge-timing.com/alge/download/software/AlgeTimyUsbDLLExample.zip) into the current user's local application data, outside event files and the repository. Afterwards USB timing works offline.
- Use **PC Timer** on the device. Enter its firmware version in the connection settings for the session record. Leave USB ID empty for automatic selection: the first connected Timy is selected; after it disconnects, the next newly connected Timy can resume capture. In a single-device capture each reconnection starts a separate clock context; the devices of a multi-device capture share one clock group because their clocks are set to the same time. When a device's clock resets (its time jumps back more than five minutes), its later impulses get a clock context of their own, so elapsed times between that device and the others require review. The interruption remains visible for review. The SDK ID identifies a connection, not a permanent device identity, so verify the intended device after reconnecting.
- With several Timys, supply the required current USB ID. Explicit selection never switches IDs automatically; if replugging changes that ID, disconnect capture and reconnect with the current selection. Other connected devices are not merged into the selected stream.
- Set/check the device clock and the date in OpenSkiTime before connecting. Use the device's maximum time-of-day precision, consistent with its printed tape; do not set the device output to hundredths merely because race results use hundredths. The application does not reset the clock, clear device memory, change firmware or send result data to the timing tape. Check the device's handshake configuration if USB times stop arriving; the PC Timer documentation describes the RTS/CTS setting.
- The main application remains .NET 10. ALGE's current mixed-mode library requires a small, isolated .NET Framework 4.8 Windows helper, included in the build. It forwards both original SDK byte/text fields to the application. No PowerShell execution-policy changes are needed. The helper currently requires x64 Windows.
- Driver and vendor libraries are not redistributed in the repository/installer. Bundling them requires redistribution terms to be confirmed. Do not disable application control or antivirus to make them run; resolve a blocked component with a trusted signed vendor package/deployment.

Timy3 USB connection, cable unplug/reconnect in automatic selection mode, subsequent device-keyboard C0M/C1M reception and persisted-data reopening have been verified with driver 2.80.0.0. These button events had hundredth precision and remain flagged as manual; they do not verify start-gate/photocell accuracy. Electrical impulses, firmware variants and recovery of impulses generated while disconnected still need rehearsal.

The current ALGE USB SDK supplies a defective byte-array field alongside its untrimmed ASCII text. OpenSkiTime preserves both SDK fields in each captured message and decodes the text only after storage. Unknown/non-ASCII content requires review. The stored SDK envelope is retained unchanged for replay and diagnostics.

## ALGE MT1

**USB / serial:** select the MT1's virtual COM port, refresh ports if necessary, and match the device's serial settings. The adapter defaults to 38400 baud, 8 data bits, no parity, 1 stop bit and no handshake. It retains fragmented ALGE ASCII input and retries an interrupted connection. In a single-device capture different connections are separate clock contexts: an elapsed time spanning a reconnect requires review.

**ALGE Results:** select **MT1 · ALGE Results** for a role, enter the account's username and choose the MT1 device (after **Fetch devices** in Settings, or type its ID) and channel. Each role may use its own device and account, for example intermediates operated by different clubs. The account needs the **Timekeeper** role. Set the device clocks in ALGE Results as for any other timing device; OpenSkiTime uses the time of day of the device clock ALGE Results reports (`timestamp + timeOffset`), like every other device, and has no time zone or date logic in timing. History is read from when the run's capture first started, so triggers during an interruption are recovered.

Triggers arrive by **realtime push**: one STOMP-over-SockJS connection per account subscribes to `/topic/device/{deviceId}/trigger` for each configured device, as documented by the ALGE Results API. A trigger typically arrives a few hundred milliseconds after the impulse. Right after every (re)subscription, and then every five minutes, a REST count check per device channel reads the recent ten minutes of history when the count changed; the full history since the capture started is read on every (re)subscription and about every ten minutes, also catching server-side edits, so a trigger the push missed is still recovered. STOMP heartbeats every 10 s detect a dead connection; silence for 30 s replaces it. While push is unavailable, REST polling every 2 s keeps timing flowing, reading the full history every five minutes so that triggers a device uploads late with older timestamps are also found, and push is retried with growing, jittered delays (up to 60 s). One notice is recorded per network interruption, not per reconnect attempt. The authorization token is reused across reconnects; sign-in is repeated only after the server reports an expired token, and the documented API quota response pauses requests for 90 s. A quota response or network failure during a periodic check while push works postpones the check and keeps the push connection. A response that breaks off or has an unexpected shape is retried like any network failure. Received push messages and history pages are preserved before interpretation, whatever their content; triggers of a subscribed device on channels no role uses are journalled as information for the Settings signal monitor and never timed; duplicate impulses do not time twice, and deletions or other server changes require review. A trigger deleted on ALGE Results appears as a device correction with its time and channel; the original trigger and its assignment stay until the operator reviews them. It is a read-only consumer and sends no device/trigger modifications. Cloud timing is not a substitute for local USB/independent backup timing.
`scripts/alge-results-probe.ps1` checks an account and device outside the application: it signs in once (the password is asked locally and never printed), subscribes to the device topic and prints each pushed trigger with its device time and delay, then compares the REST count. It sends no device commands.

Passwords remain in memory unless **Remember password** is selected. On Windows, remembered passwords use the current user's Credential Manager, separately per account; uncheck it when connecting to remove that saved password. Tokens, passwords and login responses are never stored in event files or timing traces. Live MT1/cloud operation remains unverified without the physical device/account.

## Results and recovery

- Calculation uses one integer 100 ns scale for every source, subtracts finish minus start at full received precision, then truncates each run's elapsed time to hundredths. Observation times show seven decimal places; trailing zeroes do not imply better device accuracy. At least millisecond source precision is required for automatic electronic timing; homologated timers must provide 0.0001 s or better under Timing Booklet 16.1. Equal times share rank (1, 1, 3). Combined results sum the truncated run times. Receive time is never used as race time.
- Hand/backup times require the FIS EET correction, whose average is rounded before calculating the replacement time-of-day. This calculation/report and numeric time correction are not available in the current race UI. Do not substitute a raw hand/B finish for an A finish. Device-keyboard impulses are flagged but provisional calculations are not proof of a valid replacement time.
- Missing starts/finishes, extra assigned impulses, clock resets and unrecognized/device-correction input require review. A device correction line (for example a cleared impulse reprinted minutes later) is placed at its own time without moving the device clock, so it is never taken for a clock reset. Control bytes inside a device line (NUL, STX/ETX, XON/XOFF) are ignored when reading it; the original bytes remain in the journal. Times spanning different ASCII connection clocks, less than 0.01 s or over two hours are not silently accepted. Device keyboard impulses are marked for backup verification. Unsupported penalties/reruns are not inferred.
- Original bytes, protocol version, receive sequence/time, device/date/channel settings and operator are kept in the `.ost` file. Corrections contain operator, reason, time, old/new values and raw references. SQLite rejects updates/deletes to raw input and audit rows.
- A storage failure keeps pending input in memory, shows **CAPTURE NOT SAVED**, and blocks close/file switching. Restore writable storage and use **Retry storage**, then disconnect. The bounded queue applies backpressure; hardware buffers can still fill during a prolonged fault.
- An unexpected application exit is detected on reopening and shown as an unresolved observation. Committed input and corrections replay; data still in a device/OS buffer or not durably committed may need recovery from device memory/independent timing. This is not a zero-loss guarantee for power failure or a failed disk.
- Disconnect before transferring the series. Use **Backup / transfer** for a consistent SQLite copy, including raw input and audit. Keep one authoritative event copy; no merging of independently timed copies is provided.

## Optional B and hand evidence

B capture is an operator aid for comparison and the timing report. It never assigns A impulses, changes official timing, seeds a later run or publishes results. B, hand-start and hand-finish sessions use separate auxiliary tables and immutable raw-packet journals inside the portable series file. A and auxiliary sources share file ownership but retain independent queues, faults and stop controls. Disconnecting one does not release another source's ownership. Closing or switching the series drains every connected source; unsaved auxiliary input requires storage recovery before the file can close.

**Live B Clock.** Assign **B Clock Start** and **B Clock Finish** in **Settings → Timing devices** (see [Settings](settings.md#timing-devices)). B is optional; without it nothing is connected and no B warning is shown. When B is configured, it connects automatically as a live auxiliary capture right after primary timing connects, including automatic connection on entering a run or returning from Settings, and on every reconnect. It follows the active A run and disconnects together with A and when the application closes. Supported transports reuse the Timy USB, MT1 serial, ALGE Results and replay adapters; B Clock Start and B Clock Finish may use the same or different devices, which must be independent of primary timing. Dual-Timy USB operation requires distinct explicit USB IDs and physical acceptance testing.

B is strictly isolated from A. B starts only after A is capturing and runs detached from it: an invalid B configuration, a missing device or file, a failed connection, malformed B data, a failed comparison or a slow B source never delays, blocks or rolls back A connection, capture or run switching. Such failures appear only in the B Clock status. **Retry B Clock** (or retry B storage after a storage fault) and **Disconnect B Clock** in Settings act on B alone.

The race view shows a compact **B Clock** status next to **Show B**: *not configured*, *connects with timing*, *connecting…*, *OK*, *waiting for B*, *missing signal*, *time difference warning* or *device unavailable*. Problem states are highlighted in amber. Temporary B and hand device imports for the timing report are no longer connected from Settings. Automatic device-memory download is not implemented.

**Show B** opens a read-only timestamp and elapsed-time panel for 30 seconds without moving keyboard focus. A red warning and an amber button identify missing or discrepant B evidence; hiding or expiring the panel does not clear unresolved comparisons. An unconnected B source causes no missing-signal warning. Monitoring begins with A observations arriving after the live B connection is established, and excludes earlier run history. Unique matching uses a broad two-second window; ambiguous matches require operator review.

The default operational warning thresholds are 1 ms at start, 10 ms at finish and their sum for the elapsed-time difference. Missing-signal grace defaults to five seconds, with at least ten seconds for ALGE Results polling/history recovery. The B Clock section of the timing-device settings allows these limits to be changed. These are assistance thresholds, not a claim that FIS specifies a universal race-finish A/B tolerance. The FIS synchronization test using a common impulse is a separate check. B details show full received precision; receiving or displaying B never applies an EET correction.

Live B follows an A run change without interrupting A. A partially received auxiliary message stays in its original run until complete; while this boundary is pending the display explains that B has not followed the new run. Disconnecting B remains available and records an incomplete message for review if the source never completes it. Device selection, date/channel mapping, received bytes, source precision and capture operator travel with backups; credentials and machine preferences do not.

All sources, including ALGE Results, report device clock time, and the devices' clocks are set to the same time, so A and B are compared directly. There are no time zone or UTC offset settings. Original decoded timestamps and raw packets remain unchanged.

## Practice without hardware

Use a separate test event file. Choose **Simulator** in Settings and save, then return to Timing and check the expected bib. Enter a device time such as `12:00:00.0000`, and press **Test start**. Check the expected finisher, enter `12:01:02.3456`, then **Test finish**. The result is `1:02.34`. **Test I1**, **Test I2**, etc. feed their respective configured intermediate channels. **Replay file** reads raw ALGE ASCII bytes through the same journal/decoder pipeline. Training/replay and real capture cannot be mixed in the same run.
