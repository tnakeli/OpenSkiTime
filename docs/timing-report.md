# Timing report

**7 Timing report** prepares the FIS alpine Timing and Data Technical Report inside the event series. It supports the application's standard DH, SG, GS and SL races. XML transmission remains **test-only**, just like Results. There is no PDF output, Timing Support Systems form or automatic EET calculation.

## Prepare and review

Choose the competition in the shared header. Competition identity and TD come from Competitions. Entering or reopening the report, or changing competition, loads that competition's committed A and B observations from its saved runs, independently of the race most recently displayed in Timing. The report does not poll timing sources in the background: its displayed evidence stays stable while you work. There is no separate report run selector or refresh button; reopen the report to load newer timing. First/last samples follow actual finish order, not bib order. Physically completed runs remain eligible for these samples after DSQ or another classification removes the official result time; their paired timestamps retain the measured net, or the active audited correction. The fastest eligible classified A result is filled automatically. Manual net-time corrections require an explanation and replacement source; they are not silently classified as original A evidence.

In Settings, save reusable equipment, Chief of Timing and Calculations and Timekeeper details. New reports copy these defaults into the portable event file. **Use saved Settings defaults** explicitly replaces the report's effective defaults; changing Settings alone does not change existing reports. Results Software is always OpenSkiTime and its build version.

Select the FIS timing level, enter the synchronization time and common-impulse checks, then review the run evidence. Hover over the level selector for the alpine category meanings: level 0 covers Olympic/World Championship/World Cup events; level 1 covers the listed continental cups, Universiade and Junior Worlds; level 2 is National Championships; level 3 includes ordinary FIS, junior and the other listed categories; level 4 is Entry League. The full category codes follow Timing Booklet 2.67, section 1.1, page 4; Para Alpine's separate classification is not used. Synchronization instructions are available as a tooltip over the synchronization fields (section 3, page 8). If separate start timers are configured, their check fields appear. Synchronization evidence is deliberately not inferred from PC connection time or an arbitrary race impulse. The booklet's 0.001-second requirement applies to the common-impulse check at least one minute after synchronization.

**Best A** uses classified finishers with eligible, unmodified electronic A impulses. Device keyboard impulses such as Timy `C0M`/`C1M` and replacement net times remain visible in the A grid but are excluded from Best A. When no eligible time exists, the run shows the reason and a tooltip explaining the source requirement; it does not fabricate an electronic result from manual evidence.

**B system** and **Hand timing** contain editable time-of-day cells alongside read-only A times. Use `HH:mm:ss` with the source's fractional digits, up to seven. Unknown values remain blank. Explain missed-A times and any relevant run problems. Edits save automatically, including incomplete drafts; no **Save report** button is needed. Pending edits are saved before switching competition. Invalid timestamp entries remain visibly unsaved until corrected. The operator and change reason are retained with each saved revision.

Review the source records, check the review/certification declarations, and select **Create approved XML**. Approval validates the reviewed report against the latest committed A data without refreshing the displayed evidence, and checks required fields, precision and reviewed associations. If the source changed, reopen the report and review it again. Approved XML revisions retain their exact bytes and cannot be changed by later edits. History restoration creates another draft revision and clears its certification.

## Optional B capture

Use **Settings > Timing devices** to configure an independent B source. Timy USB, MT1 serial and ALGE Results use the same transport/decoder families as A. Explicitly select different devices; the application rejects a shared COM port, overlapping ALGE device IDs and ambiguous dual-Timy selections. The separate B connection is a convenience for the timekeeper and never provides an automatic fallback into A results or live publishing.

Live B follows the active A run independently. When one source uses UTC (ALGE Results) and the other uses local clock time, set the local UTC offset explicitly in connection settings. Unspecified mixed clock contexts remain unmatched with a warning; raw observations are never rewritten. In Timing, **Show B** displays corresponding start/finish timestamps and elapsed-time comparisons for 30 seconds, without taking keyboard focus. An amber button and red message identify discrepancies or missing signals. Hiding the detail panel does not acknowledge or clear unresolved warnings.

The initial operational warning thresholds are **1 ms at start** and **10 ms at finish**, adjustable in Settings. These are monitoring defaults, not a claim that FIS imposes those two race-impulse limits. A finish-cell pair can be triggered at slightly different instants. Missing B events receive a grace period (default 5 seconds; ALGE Results has a minimum of 10 seconds for polling/history delay). Comparison starts with new A observations after B connects, so connecting late does not report the whole earlier race as missing.

To import a temporarily connected clock, choose the saved run and source role (**B**, **HandStart**, or **HandFinish**) and disable live B monitoring. Receive the device's output and disconnect after the saved-packet status is complete. The report loads the saved evidence when opened for that competition. ALGE Results requires its network service; locally attached devices and saved evidence work offline. Request memory output on the device where required; the application does not claim a tested automatic memory-download command for every model.

## Receipt and screen images

Only printed ALGE receipts and images of computer displays are in scope; handwriting recognition is not provided. OCR runs locally using the bundled Tesseract engine/model. No race image is sent to an online recognition service.

1. Choose the image target run in **Import review** before choosing/dropping images. This picker applies only to image evidence; the report itself loads all saved runs for the selected competition. A cleared selection remains empty until a valid target run is chosen.
2. Drop one or more images from one device into **B system**, **Hand start clock** or **Hand finish clock**. A B receipt may contain both start and finish channels. Hand-start and hand-finish image sets are separate. Supported input is PNG, JPEG, BMP or TIFF, at most 20 MB per image and 100 MB per batch.
3. In **Import review**, inspect the proposed timestamp, difference from A and original image. **Original size** enables horizontal and vertical scrolling for close inspection of large screen photographs. The optional device label distinguishes saved image groups. The matching tolerance is editable; defaults are one second for B and two seconds for hand timing. This search tolerance is separate from the live B warning limit.
4. Only a unique association in both directions is proposed. Overlapping photographs do not create duplicate assignments. Ambiguous matches and unrecognized timestamps remain blank. Edit unresolved values in the B/Hand grid after checking the originals.
5. Select the proposals to use and confirm that they were checked against the images. Existing values are preserved unless **Replace existing values explicitly** is selected. Acceptance commits exactly the reviewed changes and history. Reopening the same report reloads timing while preserving the proposal grid, selected row, Use choices and selected image. New raw packets that leave the reviewed A timestamps and report values unchanged preserve verification. If those values change, the preview is marked stale and cannot be accepted; select **Preview saved images** to regenerate it against the reopened report's timing. Acceptance also rejects changes committed after the displayed snapshot. Previewing saved images preserves the image you chose in the picker. Selecting a proposal opens its source image; choosing another image selects its corresponding proposal without changing the image again.

Original images, recognized text, engine identity and accepted source references stay in the series file. Reading an image is not verification: the timekeeper remains responsible for the report. Failed recognition still retains the original image for manual review when the import is saved. Committed OCR tests use synthetic receipts. For a detected column of numbered ALGE records, recognition also reads individual rows at two scales. If background noise obscures the record prefixes, a fallback locates repeated ALGE channel words and applies local contrast correction to a working copy of the receipt area. Nearby numeric words extend that area to preserve longer records. Conflicting numeric values, precision or explicit channels mark the entire physical row for manual review, even if only one alternative would fall within matching tolerance. Potentially clipped text at the image or fallback working-area boundary also requires review. These rows remain excluded when saved images are reopened or XML is validated. Open **Recognized text / review flags** to inspect the retained readings. Original image bytes remain unchanged, and working-copy coordinates are mapped back to the original image. Photographs with blur, folds, poor contrast or unusual website layouts still need operator review. To use a newer recognizer for an already saved image, import the original again; **Preview saved images** uses the stored recognized text.

## Export and FIS test transmission

Results and Timing report use the single key at **Settings > FIS**. The API uses endpoint-specific authentication headers internally. Equipment lookup and submission do not require a second secret. XML uploads require the appropriate FIS account permissions.

**Export approved XML** writes an exact approved revision and suggests a `-timing-report.xml` suffix to avoid overwriting an exported result file. API submission uses the prescribed NSA/codex filename from the immutable revision. **Send XML - test mode** submits only that saved revision; it cannot publish official results. **Check FIS status** resumes using the persisted submission UUID after reopening the file. **Stop FIS check** cancels waiting without issuing another upload. Transport acceptance and completed FIS processing are separate states. An uncertain network result is not automatically retried as a new upload.

The supplied XML description labels one `Allresults` attribute `System`, while its full example uses `SystemA`. The implementation follows `SystemA` in that example. Live FIS acceptance of the generated report remains an external interoperability check. A completely unused A/B system exception (`used=no` / `Notused`) is not implemented in this standard dual-system workflow; incomplete mandatory evidence prevents approval.

## Offline operation and builds

Report editing and receipt import are available throughout the race: before starts, with racers on course, during pauses and between runs. A, B and hand clocks can remain connected; report preparation never requires a completed run or disconnection. Image archival commits the complete batch while timing input continues through its durable capture queue. XML approval separately requires complete timing results, resolved capture history and all mandatory reviewed evidence; the current clocks may remain connected during approval.

Raw auxiliary packets, manual changes, original images, report revisions and submission history travel with the `.ost` database and its backups. Reusable preferences and credentials remain separate. Current development format `/4` creates new series files directly; incompatible older files are rejected unchanged, without migrations.

The new recognition adapter is isolated from domain calculations. The first build downloads a pinned Apache-2.0 English/numeric OCR model from `tesseract-ocr/tessdata_fast`, verifies its SHA-256 and copies it beside the application. Subsequent cached builds and runtime recognition work offline. Keep the `tessdata` directory and native OCR libraries with the application. On Windows the native engine requires the Microsoft Visual C++ 2015-2022 x64 runtime. Linux recognition/device packaging remains unverified.

## Verification boundaries

Automated coverage exercises the real offline OCR adapter with synthetic images, deterministic matching, operator acceptance/reopening, immutable XML/history, A/B isolation, raw recovery, backup/restore, test-only FIS request contracts and desktop controls. Autosave regression coverage checks separate competition timing sources, preservation of pending edits when switching competition and an empty image-run selection without a binding conversion error. Physical dual-Timy operation, automatic device-memory retrieval and real FIS Timing report acceptance are not established by these tests. No production submission is performed by implementation tests.

Local verification on 2026-10-03: Release builds completed without warnings or errors. The active rewrite solution passed all 302 tests (240 application/domain/persistence, 56 desktop, 6 live-process), with zero failures or skips. Report, navigation and Settings layouts were rendered and inspected at compact and normal sizes; tests also check original-size image scrolling and that showing B does not shrink timing queues. Image import is tested through the view model with real OCR; native operating-system file drag/drop and physical devices remain rehearsal checks.

Receipt-photograph follow-up (2026-10-03): tested one operator-provided photograph locally without adding it or its real timestamps to Git. The initial adapter extracted 22 timestamp candidates. After column/row recognition and stricter parsing, 45 of 67 manually transcribed reference timestamps appeared exactly among the usable readings; additional readings were not all correct. This is a single-image check, not a general accuracy claim. Obstructed and disputed rows still require manual work. No corresponding A capture was supplied, so real competitor association was not established by this photograph test. Synthetic tests cover spaced ALGE punctuation, refusal to extract partial corrupted tokens, row-level OCR conflicts and full-precision recognition.

Background-noise follow-up (2026-10-03): a second operator photograph contained 29 manually checked complete timestamps. The earlier recognizer did not detect the receipt column and parsed seven correct timestamps. Channel-word localization, local contrast correction and boundary review produced 20 usable readings, all with the expected time, hundredth precision and channel, with no additional incorrect timestamp candidates in this photograph. The other nine reference timestamps remain unresolved. This is a single-image result, not a general accuracy guarantee; competitor association was not tested. The original photograph and reference values remain outside Git. Synthetic regression fixtures cover leading noise, uneven lighting, long records, original-coordinate mapping and exclusion of clipped fractions.

Follow-up validation: 243 application/domain/persistence/recognition tests, 61 desktop tests and six live-process tests passed across the validation runs. The desktop Release build completed with zero warnings or errors in an isolated output directory because the running application locked its normal output. One desktop process test initially failed to locate artifacts under the isolated layout; it passed when rerun from its expected directory, together with the real-OCR import/acceptance/reopen test. Native drag/drop and physical devices were not retested.
