# Timing report

**7 Timing report** prepares the FIS alpine Timing and Data Technical Report inside the event series. It supports the application's standard DH, SG, GS and SL races. XML transmission remains **test-only**, just like Results. [PDF Factory](pdf-factory.md) prints the saved report as the FIS Timing & Data Technical Report Alpine form. The Timing Support Systems form and automatic EET calculation are not implemented.

## Prepare and review

Choose the competition in the shared header. Competition identity and TD come from Competitions. Entering or reopening the report, or changing competition, loads that competition's committed A and B observations from its saved runs, independently of the race most recently displayed in Timing. The report does not poll timing sources in the background: its displayed evidence stays stable while you work. There is no separate report run selector or refresh button; reopen the report to load newer timing. First/last samples follow actual finish order, not bib order. Physically completed runs remain eligible for these samples after DSQ or another classification removes the official result time; their paired timestamps retain the measured net, or the active audited correction. The fastest classified result is filled automatically, including manual impulses and active audited net-time replacements. Manual net-time corrections require an explanation and replacement source; they are not silently classified as original A evidence.

In Settings, save reusable equipment, Chief of Timing and Calculations and Timekeeper details. Reports always use the saved Settings values; **Edit in Settings** opens the Timing report settings tab. Saving Settings updates the open report, and opening another report applies those saved values. Each saved report revision retains its equipment snapshot in the portable event file; approved XML remains immutable. Results Software is always OpenSkiTime and its build version.

Select the FIS timing level, enter the synchronization time and common-impulse checks, then review the run evidence. Hover over the level selector for the alpine category meanings: level 0 covers Olympic/World Championship/World Cup events; level 1 covers the listed continental cups, Universiade and Junior Worlds; level 2 is National Championships; level 3 includes ordinary FIS, junior and the other listed categories; level 4 is Entry League. The full category codes follow Timing Booklet 2.67, section 1.1, page 4; Para Alpine's separate classification is not used. Synchronization instructions are available as a tooltip over the synchronization fields (section 3, page 8). If separate start timers are configured, their check fields appear. Synchronization evidence is deliberately not inferred from PC connection time or an arbitrary race impulse. The booklet's 0.001-second requirement applies to the common-impulse check at least one minute after synchronization.

**Best A** is populated from the fastest classified result with a time. Timy keyboard impulses and active audited corrections are included. This summary does not reclassify their provenance: replacement declarations still explain any times that did not come from the original System A measurements.

**Times** contains synchronization, read-only A and net times, and editable B and hand-clock cells. Overview contains equipment, comments, review and export controls. Each run asks whether all times came from System A. If not, use **Add replacement** to enter each affected bib, choose its run, open the reason dropdown (Batteries, Snow obscuration, Wire break, Photocell alignment or Other) or type a custom explanation in the adjacent field, and select System B or Manual as the replacement data source. Only runs without the all-System-A declaration are available for replacement rows. Checking that declaration removes that run's replacement rows from the draft. Saved all-System-A reports ignore historical replacement rows when reopened; detected rows are not merged into an existing draft. Rows can be removed; detected manual/corrected results still need declarations before XML approval. Use `HH:mm:ss` with the source's fractional digits, up to seven. Unknown values remain blank. Explain missed-A times and any relevant run problems. Edits save automatically, including incomplete drafts; no **Save report** button is needed. Pending edits are saved before switching competition. Invalid timestamp entries remain visibly unsaved until corrected. The operator and change reason are retained with each saved revision.

Review the source records, check the review/certification declarations, and select **Create approved XML**. Approval validates the reviewed report against the latest committed A data without refreshing the displayed evidence, and checks required fields, precision and reviewed associations. If the source changed, reopen the report and review it again. Approved XML revisions retain their exact bytes and cannot be changed by later edits. History restoration creates another draft revision and clears its certification.

## Optional B capture

Use **Settings > Timing devices** to configure an independent B source. Timy USB, MT1 serial and ALGE Results use the same transport/decoder families as A. Explicitly select different devices; the application rejects a shared COM port, overlapping ALGE device IDs and ambiguous dual-Timy selections. The separate B connection is a convenience for the timekeeper and never provides an automatic fallback into A results or live publishing.

Live B follows the active A run independently. When one source uses UTC (ALGE Results) and the other uses local clock time, set the local UTC offset explicitly in connection settings. Unspecified mixed clock contexts remain unmatched with a warning; raw observations are never rewritten. In Timing, **Show B** displays corresponding start/finish timestamps and elapsed-time comparisons for 30 seconds, without taking keyboard focus. An amber button and red message identify discrepancies or missing signals. Hiding the detail panel does not acknowledge or clear unresolved warnings.

The initial operational warning thresholds are **1 ms at start** and **10 ms at finish**, adjustable in Settings. These are monitoring defaults, not a claim that FIS imposes those two race-impulse limits. A finish-cell pair can be triggered at slightly different instants. Missing B events receive a grace period (default 5 seconds; ALGE Results has a minimum of 10 seconds for polling/history delay). Comparison starts with new A observations after B connects, so connecting late does not report the whole earlier race as missing.

To import a temporarily connected clock, choose the saved run and source role (**B**, **HandStart**, or **HandFinish**) and disable live B monitoring. Receive the device's output and disconnect after the saved-packet status is complete. The report loads the saved evidence when opened for that competition. ALGE Results requires its network service; locally attached devices and saved evidence work offline. Request memory output on the device where required; the application does not claim a tested automatic memory-download command for every model.

## Receipt and screen images

Only printed ALGE receipts and images of computer displays are in scope; handwriting recognition is not provided. OCR runs locally using the bundled Tesseract engine/model. No race image is sent to an online recognition service.

1. In **Times**, click the B, hand-start or hand-finish button on the relevant run card. The receipt dialog opens first. Use **Open images**, drop image files into the dialog, or **Paste image**. Ctrl+V pastes an image; Ctrl+C also reads a copied image when focus is outside a text editor. Windows supports PNG and bitmap clipboard images without temporary files. B receipts may contain both channels. PNG, JPEG, BMP and TIFF files are supported, up to 20 MB per image, 100 MB and 50 images per dialog.
2. The dialog reads images locally and shows detected text, original images and matches for only the first/last report samples. It matches timestamps rather than bib numbers. The grid identifies the sample and start/finish position, current value, proposed timestamp and difference from A. There is no separate preview step or device-label field. Resize columns or drag the table/image divider for more room.
3. **Select all** selects every matched timestamp and leaves unmatched rows unselected. Existing different values show a replacement message and are initially unselected; selecting those rows explicitly authorizes replacement. Review selected matches and press **OK**. Acceptance uses the displayed A/B snapshot without rereading live timing packets. Report changes or conflicting report writes still reject acceptance. The operator identity and an automatic change reason remain in audit history without separate form fields.
4. Closing or cancelling discards images, OCR text and proposals. None of them is written to the series database. Only accepted report values and audit history are saved. Failed recognition permits inspection in the dialog without archival. Keep original receipts separately when required.

OCR uses synthetic regression fixtures. Conflicting row readings and potentially clipped fractions require manual review. Photographs with blur, folds or poor contrast may need manual entry in Times.

## Export and FIS test transmission

Results and Timing report use the single key at **Settings > FIS**. The API uses endpoint-specific authentication headers internally. Equipment lookup and submission do not require a second secret. XML uploads require the appropriate FIS account permissions.

**Export approved XML** writes an exact approved revision and suggests a `-timing-report.xml` suffix to avoid overwriting an exported result file. API submission uses the prescribed NSA/codex filename from the immutable revision. **Send XML - test mode** submits only that saved revision; it cannot publish official results. **Check FIS status** resumes using the persisted submission UUID after reopening the file. **Stop FIS check** cancels waiting without issuing another upload. Transport acceptance and completed FIS processing are separate states. An uncertain network result is not automatically retried as a new upload.

The supplied XML description labels one `Allresults` attribute `System`, while its full example uses `SystemA`. The implementation follows `SystemA` in that example. Live FIS acceptance of the generated report remains an external interoperability check. A completely unused A/B system exception (`used=no` / `Notused`) is not implemented in this standard dual-system workflow; incomplete mandatory evidence prevents approval.

## Offline operation and builds

Report editing and receipt import are available throughout the race: before starts, with racers on course, during pauses and between runs. A, B and hand clocks can remain connected; report preparation never requires a completed run or disconnection. Receipt recognition runs in memory while timing input continues through its durable capture queue. XML approval separately requires complete timing results, resolved capture history and all mandatory reviewed evidence; the current clocks may remain connected during approval.

Raw auxiliary packets, manual changes, report revisions and submission history travel with the `.ost` database and its backups. Reusable preferences and credentials remain separate. Current development format `/4` creates new series files directly; incompatible older files are rejected unchanged, without migrations.

The new recognition adapter is isolated from domain calculations. The first build downloads a pinned Apache-2.0 English/numeric OCR model from `tesseract-ocr/tessdata_fast`, verifies its SHA-256 and copies it beside the application. Subsequent cached builds and runtime recognition work offline. Keep the `tessdata` directory and native OCR libraries with the application. On Windows the native engine requires the Microsoft Visual C++ 2015-2022 x64 runtime. Linux recognition/device packaging remains unverified.

The original photograph and reference values remain outside Git.
