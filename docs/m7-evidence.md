# M7 evidence — FIS Alpine results

Current storage policy (2026-10-02): database migrations and migration tests have been removed from the rewrite. New development files use the current model directly; incompatible files are rejected unchanged. Backup/reopen, replay and immutable-history checks remain. Migration references below describe historical milestone verification, not the current implementation. See [development database policy](development-database-policy.md).

Implemented scope: the Results view loads the final saved start lists and replayed timing for a FIS competition. It requires every starter to have a time or classification; extra unassigned/review timestamps remain preserved and are reported without blocking a complete result. The TD can inspect final/individual run times, statuses, race points, the five best classified within the top ten (including tenth-place ties), the five best starters, sums A/B/C, the calculated and applied penalty, and the double-maximum floor. Race points use the discipline's 2026/27 F value. The drawn points-list snapshot is used; later FIS downloads cannot change the calculation. Category minimum, maximum and adder must be entered from the current list's first page.

The TD enters FIS calendar category, jury and per-run course details, then approves. Approval requires stopped capture, a current series revision and an unchanged source fingerprint covering start lists, sessions, original packets and timing audit. The event-series database stores immutable, numbered approvals with the exact UTF-8 XML bytes. Reopening and exporting a saved revision reproduces those bytes. Existing `.ost` files are backed up before the new migration. No API key, personal sample file or live FIS submission is used.

Rule sources: attached *FIS Points Rules 2026/27* (4.4–4.5), *ICR 04-09-2026* (617.3), and *Alpine result XML 2.12* (`result-xml-alpine.md`). The older 2022 penalty sheet was used for presentation only. The XML tables, rather than inconsistent example casing/content, govern element names. Covered profiles are standard SL/GS two-run and DH/SG one-run FIS competitions. Special events, combined/parallel/team formats, FIS upload, timing report and PDF are outside this increment.

Verification: full rewrite solution build and tests; deterministic penalty/rank/status/XML cases; SQLite approval, reopening, byte equality and update/delete trigger test; headless 1366-pixel view rendering. The live FIS receiving service and official schema validator were unavailable, so acceptance of the exported XML and category values by a TD/FIS remains outstanding. No physical race or device trace was used for M7 acceptance.
