# M3 competitor desk and TSV exchange evidence

The Competitors view has one editable grid and one pending change list. Manual cell edits, competition entry checkboxes, Excel TSV paste and row deletion remain local until **Commit Changes** writes them in one SQLite transaction. **Restore** reverses one changed field, entry or deletion; a new row can be removed as one change. The blank row remains available for direct entry. Changed cells are yellow and pending rows have a compact change marker; both states are derived from saved values so they clear after restore or commit. The selected row has its own consistent selection color. Men/Women are combo-box choices in the grid and category editor.

The grid exposes competition participation, but no bib or competitor status. Bib assignment belongs to a later Draw view. Paste rejects bib columns here; copied TSV excludes bibs. The grid context menu holds copy, paste, delete and row restore. The separate import-review panel, row-save/undo controls, selected-competitor participation panel, export-to-file button and legacy-conversion preview were removed from this surface. Legacy conversion code and earlier M2/M3 tests remain historical/reference material.

**Code** is the first competitor field in the grid and copied TSV. TSV import accepts both `Code` and the earlier `Fed ID` header; a new competitor can be entered with Code alone and completed from the cached FIS list. In a pasted competition column, a blank cell now explicitly removes participation; absent competition columns leave participation unchanged. Scalar blank cells still preserve saved values. Selected competitor rows can receive one participation checkbox change together, and the pending list shows Code, surname and old → new values.

Release tests cover typing into the blank grid row, Tab navigation, Delete staging, manual and pasted changes in one list, per-change Restore, commit, category behavior and reopening a transferred file. A SQLite test verifies that a later invalid batch row rolls back earlier inserts, entry changes and deletion, and that stale revisions are rejected. The existing parser tests still cover TSV quoting, identity matching and receipt-based import behavior; the current grid uses the parser's preview only and commits through the new desk batch operation.

A 1280 px headless frame with pasted edits and the pending change list was rendered and inspected for alignment, clipping and contrast. Native Windows keyboard, focus, clipboard and visual rehearsal is still needed. The installed Debug executable was open during validation, so Release output was built and tested without disturbing it. Existing dependency NU1903 advisories remain.
